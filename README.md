## 概述

**Sieve** 是一款实验性 VST3 粒子合成器插件。它不依赖传统波形振荡器，而是将任意音频文件切片为数百个微小的"粒子"（grains），通过**经典排序算法**逐步将这些粒子从随机混乱状态排列回原始顺序——每一次元素比较与交换都会触发一个音频粒子播放，使排序过程本身成为音乐。

插件内置 **9 种经典排序算法**，每种算法因其比较模式、交换步数和执行路径不同，产生截然不同的节奏纹理和声音演变轨迹。

---

## 功能特性

- **粒子引擎**：将加载的音频文件均匀切片为 4–512 个颗粒，每个颗粒都带独立的音高和力度控制
- **9 种排序算法**：Bubble / Insertion / Selection / Quick / Merge / Shell / Heap / Shaker / Bogo
- **4 复音**：最多 4 个独立 voice，可通过 MIDI 键盘同时触发多组排序
- **暂停/恢复**：松开 MIDI 键暂停排序（保留进度），再次按键从断点继续
- **完整 ADSR 包络**：每个颗粒独立包络控制，塑造颗粒的起音和衰减
- **实时可视化**：4 行柱状图动画，每行对应一个 voice，高度代表颗粒原始位置
- **波形显示**：加载的音频波形总览，当前位置标记
- **Turbo 模式**：高性能模式，跳过比较步骤的音频触发以降低 CPU 负载
- **界面**：Current-inspired 暗色仪器界面；采样区是静态采样总览，不冒充实时示波器
- **参数帮助**：悬停任一参数或动作即可查看用途说明
- **原生接线**：WebView 参数通过 JUCE native bridge 写入 APVTS，排序状态和播放位置来自真实 DSP 快照
- **文件拖放**：支持直接拖入 WAV/AIFF/FLAC/OGG/MP3 文件
- **About 彩蛋**：点击标题"Sieve"弹出关于对话框

## 安装

1. 将 `Sieve.vst3` 文件夹复制到 VST3 插件目录：
   ```
   C:\Program Files\Common Files\VST3\
   ```
2. 在 DAW 中重新扫描插件
3. 在乐器/合成器分类中找到 **Sieve (UnpureBloom)**

macOS 归档同时提供 VST3、AU 和 AUv3 构建。VST3 放入：

```
~/Library/Audio/Plug-Ins/VST3/
```

AU 放入：

```
~/Library/Audio/Plug-Ins/Components/
```

AUv3 需要使用经过 Apple 签名的宿主/Standalone 容器；GitHub Action 当前上传的是用于验证的未签名构建。

### 操作流程

1. **加载音频**：点击 **Load** 或拖放音频文件到界面
2. **选择算法**：从下拉菜单选择排序算法
3. **调整参数**：设置切片数量、排序速度和颗粒时长
4. **按下 MIDI 键**：开始排序，每个排序步骤触发一个音频颗粒
5. **松开按键**：暂停排序（进度保存）
6. **再次按键**：从断点继续
7. **排序完成**：自动停止；再次按键重新打乱开始

## 排序算法详解

以下 9 种算法均以预计算方式生成完整的排序步骤序列，排序步进由可调节的定时器驱动，每一步触发对应位置的音频颗粒。

### 1. Bubble Sort（冒泡排序）

| 属性 | 值 |
|------|-----|
| 时间复杂度 | O(n²) |
| 空间复杂度 | O(1) |
| 稳定性 | 稳定 |

**原理**：反复遍历数组，比较相邻元素，若顺序错误则交换。每轮遍历将当前未排序部分的最大值"冒泡"到末尾。

**听觉特征**：最慢的排序方式之一。产生均匀、可预测的颗粒流。高值元素逐个移动到右侧，音频片段从低到高逐渐有序。适合营造缓慢演变的氛围纹理。

**优化**：Early exit 检测——记录每轮最后一次交换位置，已排序区间自动跳过。

---

### 2. Insertion Sort（插入排序）

| 属性 | 值 |
|------|-----|
| 时间复杂度 | O(n²) |
| 空间复杂度 | O(1) |
| 稳定性 | 稳定 |

**原理**：将数组分为已排序和未排序两部分。每次从未排序部分取出第一个元素，在已排序部分中找到正确位置插入。

**听觉特征**：前半段较快（小规模已排序区域查找位置快），后段逐渐变慢。声音呈现出"逐个归位"的节奏感，仿佛碎片正在被逐一安放到正确位置。

---

### 3. Selection Sort（选择排序）

| 属性 | 值 |
|------|-----|
| 时间复杂度 | O(n²) |
| 空间复杂度 | O(1) |
| 稳定性 | 不稳定 |

**原理**：每次从未排序部分选出最小元素，与未排序部分的第一个位置交换。逐步构建左侧的已排序区间。

**听觉特征**：交换次数少（每轮仅一次），但比较次数固定。颗粒播放集中在少数关键交换时刻，大部分时间在"扫描"（比较但不触发音频）。产生稀疏、有节奏的颗粒触达模式。

---

### 4. Quick Sort（快速排序）

| 属性 | 值 |
|------|-----|
| 时间复杂度 | 平均 O(n log n)，最坏 O(n²) |
| 空间复杂度 | O(log n)（迭代实现用栈） |
| 稳定性 | 不稳定 |

**原理**：选取基准元素（pivot），将数组分为小于和大于基准的两部分，递归/迭代地对子数组排序。使用迭代实现以避免递归栈溢出。

**听觉特征**：速度最快的高性能算法。大量比较和交换密集发生，产生丰富而快速的颗粒风暴。分区过程使音频在不同频率区域间跳跃，营造出"分治"的声音纹理——高频和低频颗粒交替出现。

---

### 5. Merge Sort（归并排序）

| 属性 | 值 |
|------|-----|
| 时间复杂度 | O(n log n) |
| 空间复杂度 | O(n) |
| 稳定性 | 稳定 |

**原理**：将数组递归地对半分割直到每个子数组只有一个元素，然后逐层合并已排序的子数组。

**听觉特征**：独特的分层结构——先从局部小范围开始排序合并，逐步扩大到全局。声音表现为多个独立的"排序岛屿"逐渐合并。前半段几乎听不到变化（在拆分），后半段合并阶段密集触发颗粒，呈现出"汇聚"效果。

---

### 6. Shell Sort（希尔排序）

| 属性 | 值 |
|------|-----|
| 时间复杂度 | O(n log² n) ~ O(n^(4/3)) |
| 空间复杂度 | O(1) |
| 稳定性 | 不稳定 |

**原理**：插入排序的改进版。先以较大间隔（gap）对元素进行插入排序，逐步缩小间隔直至 1。使用 Ciura 间隔序列：701→301→132→57→23→10→4→1。

**听觉特征**：最具音乐性的算法之一。大间隔阶段产生"粗粒度"排序——远距离的元素交换形成跨越式颗粒跳变。随着间隔缩小，排序越来越精细，颗粒播放逐渐密集。整个过程呈现从粗糙到精细的自然过渡，如同雕塑从粗胚到精雕。

---

### 7. Heap Sort（堆排序）

| 属性 | 值 |
|------|-----|
| 时间复杂度 | O(n log n) |
| 空间复杂度 | O(1) |
| 稳定性 | 不稳定 |

**原理**：首先构建最大堆（heapify），然后反复取出堆顶（最大值）放到数组末尾，重新调整堆结构。分为建堆和提取两个阶段。

**听觉特征**：建堆阶段：大量比较和交换集中在数组前半部分，颗粒密集触发。提取阶段：规律性的交换模式（根节点与末尾交换后下沉），产生可预测的节奏型。整体听感稳健、结构清晰。

---

### 8. Shaker Sort（鸡尾酒排序）

| 属性 | 值 |
|------|-----|
| 时间复杂度 | O(n²) |
| 空间复杂度 | O(1) |
| 稳定性 | 稳定 |

**原理**：冒泡排序的双向变体。交替从左到右和从右到左进行冒泡，每轮同时确定最小值和最大值的位置。又名 Cocktail Sort / Bidirectional Bubble Sort。

**听觉特征**：类似冒泡排序但更有节奏感——交替的正反向扫描产生"来回摆动"的声音纹理。颗粒从两端向中间收敛，形成对称的排序模式。比单向冒泡稍快，听觉上更有动感。

---

### 9. Bogo Sort（猴子排序）

| 属性 | 值 |
|------|-----|
| 时间复杂度 | O((n+1)!) |
| 空间复杂度 | O(1) |
| 稳定性 | 不稳定 |

**原理**：随机打乱数组，然后检查是否已排序。若未排序则再次随机打乱，重复直到偶然排好。本实现限制最大 256 次迭代以避免无限循环，使用固定随机种子保证结果可复现。

**听觉特征**：完全随机的颗粒触发。每次迭代随机交换元素，产生不可预测的混沌纹理。适合实验性噪音、glitch 效果和随机音乐生成。在大量切片时几乎不可能在迭代限制内完成排序，形成持续的随机颗粒风暴。

> ⚠️ **注意**：Bogo Sort 仅供娱乐和实验。大量切片时可能永不收敛。

## 技术架构

```
┌──────────────────────────────────────────────┐
│                  processBlock                │
│  ┌─────────┐  无锁队列   ┌────────────────┐ │
│  │ MIDI 输入 │ ────────→ │ VoiceMessage    │ │
│  └─────────┘             │ Trigger/Release │ │
│                          │ /Panic          │ │
│                          └───────┬────────┘ │
│                                  │          │
│  ┌──────────────────────┐       │          │
│  │ VoiceState [0..3]    │ ←─────┘          │
│  │  - currentValues[]   │                  │
│  │  - steps[]           │                  │
│  │  - stepIndex         │                  │
│  │  - paused/active     │                  │
│  └──────────┬───────────┘                  │
│             │ advanceVoice()               │
│             ▼                              │
│  ┌──────────────────────┐                  │
│  │ GrainVoice [0..47]   │                  │
│  │  - 48 实例对象池     │                  │
│  │  - ADSR 包络         │                  │
│  │  - 线性插值采样      │                  │
│  └──────────────────────┘                  │
└──────────────────────────────────────────────┘
```

- **C++20** / JUCE 8 / CMake + Ninja
- **线程安全**：音频线程与 GUI 线程通过无锁 SPSC 队列通信
- **对象池**：48 个 GrainVoice 实例循环复用，避免动态分配；只复用完全空闲的槽，池满则跳过该步触发（密度上限，从结构上杜绝抢占爆音）
- **排序预计算**：所有步骤在 voice 激活时一次性生成，播放阶段无计算开销

## 构建

```bash
# Windows: 要求 CMake 3.22+, MSVC 2022, JUCE 8, WebView2 SDK/runtime
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DSIEVE_JUCE_DIR="E:/path/to/JUCE" \
  -DJUCE_WEBVIEW2_PACKAGE_LOCATION="E:/path/to/Microsoft.Web.WebView2.*/"
cmake --build build --config Release
# 输出: build/Source/Sieve_artefacts/Release/VST3/Sieve.vst3

# macOS: 使用 Xcode generator，可生成 VST3/AU；Xcode 下额外生成 AUv3
cmake -B build-mac -G Xcode -DSIEVE_JUCE_DIR="/path/to/JUCE"
cmake --build build-mac --config Release
```

Windows 运行时需要系统安装 Microsoft Edge WebView2 Runtime；插件包不捆绑 WebView2 SDK、Loader 或 JUCE 源码。macOS 使用系统 WebKit，不依赖 Windows SDK。
